# Draft a message

Read the user's supplied message and intended change first. Use known names and facts; ordinary rewriting does not require contact enrichment. Improve clarity, language and sequence while staying close to the original wording unless a stronger rewrite is requested. Keep uncertainty and optionality: a proposal does not become a confirmed appointment, promise or completed action.

Select the content's target root explicitly from the request and existing owner. Never derive it from this skill's installed location. If `.agents/skill-adapters/draft.md` exists at that target root, read it for style, examples, sender identity, signature, storage and permitted delivery channels. A missing adapter blocks effects that require its identity/provider, not a text-only rewrite with sufficient supplied facts. Do not search another vault as a fallback. Personal aliases, real addresses, brand signatures and organizational examples belong in the local adapter/resources, not this public skill.

## Before showing a version

Choose one communication objective. Test every request, sensitive detail and explanation: explicitly requested, or necessary for that objective? Remove unrelated administrative asks, courtesy filler and extra conditions. Do not reintroduce a request the user removed unless a new necessary dependency arises; explain that dependency separately.

Check information sensitivity against the intended audience. An internal or personal source is not automatically shareable because it was readable. Consider both the information and its provenance, named people and foreseeable consequences. Keep routine checking invisible. If a material disclosure permission is missing, ask only about that uncertainty and continue independent drafting that does not depend on it. Never invent consent or omit a material fact merely to make a draft more persuasive.

Before the final version, make a proportional tactical pass: correct recipient and identity, truthful facts, no unnecessary commitments, no avoidable misunderstanding, preserved voice. Negotiation, employment, HR and legal commitments deserve deeper review than a routine reply.

## Channel and form

Use the recipient's language or the language explicitly requested. Preserve meaningful references, dates, amounts and names, and distinguish types of identifiers. A reply preserves the thread's subject when known. Never invent a delivery address or sender details. Ask only when unresolved identity changes the message materially.

A message must make sense to its recipient without this chat. Use a suitable greeting and one closing. Apply the selected adapter's confirmed signature once, without duplicating the closing. Natural language and shared technical terms take precedence over mechanical word replacement. Translation is composition with the same factual and delivery boundaries; an optional local glossary informs wording rather than becoming a required unavailable source.

Explicit text-only or rewriting requests return text in chat. For a requested formatted email, use `output` and the selected target's email style; keep To, Subject and Body independently copyable, supply a complete text fallback and any images separately. A local default to Outlook HTML belongs in the adapter. Browser interactions, hidden controls and scripts do not become working mail features. Where a visual genuinely improves reading, integrate explanation into one self-contained block and remove duplicate prose.

Questionnaires focus on facts the recipient can supply, not questions the user is expected to answer for them. Collaborative fragment work remains interactive only when requested; an ordinary message request receives a complete draft.

## Save and deliver

Preserve original input, shown versions and feedback at the proven content owner through its supported writer when local storage is requested or established. Separate proposed, approved, staged and sent states. Missing writer authority is a concrete limitation, never permission to write to a fallback location.

Preparing or displaying a message does not send it. A requested delivery uses the actual connected channel, recipient evidence and existing authorization; a local never-send or draft-only policy remains controlling. Do not create a mail-app draft, post to a service or change account settings as a side effect of rewriting. Show only the usable draft unless a substantive choice or limitation needs a short explanation.
