# Recheck delivered work

Recheck the result delivered in the current task. A separate subject belongs to audit; possible later improvements belong to next. Read the original request, subsequent decisions, actual output, changes and acceptance evidence. Do not invent a specification or assume earlier success messages are fresh proof.

Optionally read `.agents/skill-adapters/recheck.md` from an explicitly selected target root for specialist mail, runtime or vault checks. The installed source root is never the target. If a required provider is missing, identify that exact unverified part; run independent checks that remain possible.

## One bounded loop

1. Pin scope, requirements and the completion claim. Respect a user-selected partial check and do not call that a full recheck.
2. Challenge the key assumption with a concrete counterexample or missing acceptance test. Inspect sources and results directly. Distinguish a blocker from a speculative concern.
3. For an explicit read-only request, make no repairs, notes or tasks. Otherwise repair only safe local reversible gaps within existing authorization. External, destructive, costly, private, public or expanded effects keep their own approval and writer boundaries.
4. Verify the real changed result with appropriate tests, render/readback, current runtime or source evidence. Re-run affected checks after a repair. Passing tests alone cannot satisfy a missing user requirement.
5. Finish the required independent review before a final complete verdict. A background review still running is not green evidence. If necessary evidence or repeated repair still fails, report the remaining blocker rather than loop indefinitely or move an in-scope gap into an optional backlog.

For branch/PR changes, pin the exact diff and include selected uncommitted/untracked changes. For routing changes inspect entrypoints, references, callers and runtime loading; changing files does not prove existing sessions reloaded them. A render test is not evidence of a recipient-app paste or received message unless actually observed.

Return a concise verdict: complete, incomplete, or stopped, with the strongest evidence and material residual limitation. If incomplete, name the next concrete action. Do not add a second audit report, automatic automation proposal or new task register. A complete verdict is not permission to deploy, publish or send.
