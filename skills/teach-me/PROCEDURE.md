# Understand and apply

Start with the concrete question and likely learning gap. A short factual request needs a direct answer; do not teach an entire discipline to explain one term. Ask about prior knowledge only when it materially changes the explanation. The user can request a fast explanation, guided reasoning, hints, a check of their understanding or an explicit learning path.

## Establish source and level

Read named repositories, documents or passages before explaining how they work. For changing or high-stakes facts use current reliable sources and distinguish source fact, worked example, assumption and interpretation. An unavailable source limits the claim, not necessarily all general explanation.

Use the user's supplied numbers and tools for material arithmetic. Do not invent personal financial amounts or exact legal/bank/tax outcomes. Clearly mark fictional examples. For personal source context or a specialist calculator, read `.agents/skill-adapters/teach-me.md` in the explicitly selected target when present and use its actual domain owner/provider. Never derive that target from this skill's location. A missing required specialist blocks that personalized calculation/claim, while sourced general explanation or explicitly fictional arithmetic can continue.

## Choose the lightest useful mode

- **Direct explanation:** answer, concrete example and reusable model; no mandatory quiz.
- **Semi-Socratic:** explain briefly, ask one prediction or why-question, then wait before the dependent next lesson.
- **Hints:** while the user is solving a problem, offer the smallest useful hint rather than immediately giving the full answer. Honor an explicit request for the solution.
- **Teach-back:** when understanding is being checked, invite the user to explain in their own words and identify actual gaps in logic, completeness or misconception risk; avoid a ritual score.
- **Curriculum:** on request propose a learning goal, sequence, resources and checkpoints. A course proposal does not automatically create a project, task list or learning record.

Read [teaching techniques](references/teaching-techniques.md) for guided practice, scaffold fading or teach-back. Use only the relevant method rather than a full fixed sequence.

## Make the mechanism clear

1. Lead with the answer or hinge concept. Correct a misconception only when the user's actual wording or reasoning demonstrates it; do not assign a mistaken belief by guess.
2. Work a recognizable example from the supplied situation. Keep fictional inputs visibly fictional and preserve units and assumptions.
3. For flows, dependencies, timing or branching show the smallest useful diagram/table. A visual should clarify the relation, not decorate a single definition.
4. Extract the reusable model. Where useful distinguish mechanism (what happens), rule (what is required/permitted), and strategy (what choice follows).
5. Surface relevant unknowns and consequences. For “what am I missing?” show uncertainty → effect → source/check, not an invented minimum list.
6. In a real learning session close with one appropriate application/retrieval question or professional source check. A simple explanatory answer needs no compulsory exercise or next assignment.

Adapt pace from actual responses. Once the model is understood, move to application or exceptions. After repeated difficulty, simplify the step and supply a smaller example or missing prerequisite rather than increasing complexity. Explicit brevity remains brief.

## Boundaries and delivery

For explicitly requested adversarial testing, explain first then use the actual grill/interview procedure; ordinary learning is not an automatic adversarial round. Correct a demonstrably harmful misconception promptly with sources. Current research/comparisons use research, and a subsequent message draft uses draft only when part of the task. A product audit or recheck retains its own purpose.

Deliver the answer, appropriate example/model and only material checks. Make professional verification questions concrete when a bank, clinician, legal adviser or other specialist controls the real outcome. General explanation is not personal acceptance or advice from that authority.

Do not create automatic learning logs, daily writes, curricula or task records. For authorized preservation use the existing owner/writer and retain what became clear, why it matters and remaining uncertainty. Do not claim the user understands, a record was saved or personal advice was professionally verified without actual evidence.
