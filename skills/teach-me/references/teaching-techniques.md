# Selective teaching techniques

Use these techniques when guided practice or deeper understanding is actually requested. The main procedure controls scope, tempo and preservation; this is not a mandatory answer template.

## Hinge and worked example

Find the concept that explains why the user's current observations fit together. Name it plainly, work a small concrete example, then extract a reusable relation or decision rule. Do not assume a wrong mental model merely to set up a contrast. Use supplied numbers where relevant; invented inputs are explicitly fictional.

Choose a visual by relation: timeline for sequence, flow for transfers, compact contrast table for confusable concepts, decision tree for branches, boxes/arrows for architecture, or uncertainty/consequence/check matrix for risks. Do not impose a format when a sentence answers the question.

Separate mechanism, governing rule and strategy when they would otherwise be confused. A process example is not proof of actual legal, tax, lender or professional acceptance.

## Hints and scaffolding

For someone actively solving a problem, diagnose what they have tried and offer the least hint that changes the next move: concept nudge → analogous example → principle reminder → partial step outline → full answer with a short explanation of the decisive clue. This is an adjustable ladder, not a fixed questionnaire. Pause for the user's response before a dependent next hint; honor an explicit request for the solution.

For multi-step procedures use worked-example fading: full annotated example, partially completed example, similar problem with fewer hints, then an independent transfer case. Fade routine final steps first. Beginners may still need a complete example; once stable, extra scaffolding can get in the way.

## Retrieval and teach-back

A real learning session may close with a single useful check: recall the steps without looking, apply the model to a changed case, or explain it to a relevant audience. Evaluate coherent order, missing mechanisms and risk of teaching the wrong idea. Correct concrete errors rather than assigning a school-like score. An everyday factual answer needs no mandatory test.

Curriculum design is a separate requested mode: explicit goal, prerequisites, sequence, sources and checkpoints. No tasks or learning dossier are created merely because a pathway was proposed.

These are independently expressed teaching patterns. The reviewed predecessor cited inspiration from Matt Pocock's teach skill, citypaul's teach-me, Socratic scaffolding and worked-example-fading resources. No external package, runtime or text is required to apply the general techniques here.
