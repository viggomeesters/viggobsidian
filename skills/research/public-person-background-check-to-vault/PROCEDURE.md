# Public professional-context enrichment

Resolve the intended person and the actual purpose from the user's request or authorized dossier. Do not investigate unrelated strangers or silently expand into sensitive personal profiling. Use public, relevant sources; exclude hidden/private-source access and data-broker contact details as canonical facts. Resolve identity ambiguity before attaching findings.

Keep public source context separate from canonical contact fields, user-authored information and provider-owned account data. Record source, date, uncertainty and how identity was established. A matching name alone is not identity evidence. Do not infer private attributes, overwrite a handwritten value or replace a provider-owned field merely because a web page differs.

For a selected vault read its authority contract and `.agents/skill-adapters/public-person-background-check-to-vault.md` when present. The adapter owns the real person collection, entity/contact synchronization rules and permitted field writer. An absent required contact adapter blocks mutation, not a bounded public-source answer. This skill's location never selects the target or grants access.

Use the owner's supported transaction for authorized updates, preserve original evidence and user edits, read back affected fields and distinguish unresolved source claims from accepted contact data. Legacy recipes are not fallback writers. Research, preservation and outbound contact remain separate effects.
