# Work handoff

Choose the existing owner and the requested effect before handing off:

- **Repository work:** read [GitHub work](../../github-work/SKILL.md). It follows GitHub Issue → branch → PR → local checks and independent review → merge.
  Do not create workflowstate or load a retired workflow runtime.
  Capture-only stays capture-only; a plan-only request stops before implementation.
- **Markdown-vault task:** read [vault-task](../../vault-task/SKILL.md) and follow
  its native task workflow at the existing dossier.
- **Conversation or read-only findings:** report the result here. No taskstate
  is required merely because an idea, recommendation or possible follow-up exists.

The current user request determines whether to save, plan or execute. Continue
already authorized work without asking for the same authorization again. Preserve
the outcome, boundaries, acceptance and useful sources at the chosen owner;
create neither competing taskstate nor a global queue. External actions retain
their existing authorization boundaries.
