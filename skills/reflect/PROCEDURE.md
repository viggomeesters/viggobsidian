# Reflection router

Use the period requested or clearly established in the conversation. Ask only if the period materially changes the task and cannot be recovered. A neutral default such as the current week may be offered, not silently imposed over a stated period.

Distinguish three effects before reading or writing: a data-only summary, personal reflective coaching, or review of an agent/code session. Data-only summary stays read-only unless separately authorized. Agent-session process feedback uses [selfimprove](../selfimprove/PROCEDURE.md); an ordinary product review uses recheck instead.

For personal reflection, read the explicitly selected target's `.agents/skill-adapters/reflect.md` and its actual coaching procedure. If that private coaching adapter is required but absent, do not guess personal sources or logging behavior. A missing adapter need not block a general conversational reflection with the user's supplied context. Do not start a new check-in or impose personal storage as a hidden prerequisite.

Once routed into coaching, continue its current source and per-turn preservation contract without selecting this router recursively. Do not create a human vision update, daily/weekly entry, new logger or old runtime fallback merely because reflection was requested.
