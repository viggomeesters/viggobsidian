# Completion message

Read the original task/request and actual acceptance evidence. Use the repository issue/PR or existing note owner rather than invent a new task ID. A commit, push or previous chat claim alone is not proof of the entire result. This skill communicates an existing outcome; it does not rerun or silently complete underlying work.

Include the project/context, stable existing identity, proven completion date, concise result and useful labelled links. Do not replace an unknown historical completion date with today's date. If acceptance is incomplete, describe what is delivered and what remains without a complete/green claim for the whole.

With an explicitly chosen target root, optionally read `.agents/skill-adapters/opleverbericht.md` for the intended channel's confirmed format and storage rules. Never resolve that target from the skill source. Without a channel-specific template use concise ordinary prose or a simple table matching the request; do not fabricate brand cards or a forced format.

Verify linked targets with the supported connector/API or reader, including fragment and actual object where relevant. Authenticated access does not prove the recipient can open it. A private target may need permission; a local path is not a recipient-accessible link. Keep internal proof paths and implementation logs outside the copyable recipient message.

Preserve earlier versions and source linkage only through the selected owner's authorized writer. Reuse an existing note; do not create a second execution register solely for communication. A capture requirement does not transfer technical status ownership away from the repository. If an existing owner is absent and storage is required, use its actual supported intake rather than invent task identity or a direct writer.

Return a ready-to-copy message in the requested audience voice. Include only material outside-message caveats about missing proof or recipient access. A stored draft is not a sent message, and a completion message is not an approval to publish, deploy, update task status or contact anyone.
