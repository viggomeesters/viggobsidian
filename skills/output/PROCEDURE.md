# Output production

Identify the intended recipient, actual medium, explicit format and destination. Reuse the chosen template or established brand source before inventing a new layout. Ordinary chat is not an artifact request. Do not add an export, hosted page, report navigation or companion document merely to make a short result feel complete.

Optionally load `.agents/skill-adapters/output.md` from the explicitly selected target root. It may define local brand sources, assets, output planner/checker and writer commands. The source root of this installed procedure never chooses the target. Check an actual provider's availability before depending on it; do not replace a refused writer with an ad-hoc write.

## Select the maker

- Existing documents, slides or spreadsheets: use the matching format workflow and preserve native content, formulas, styles, sections, layouts and required editability.
- New document/report: choose the smallest format meeting its reading/export requirement. Use an established template when supplied.
- Participant-facing mail: draft owns purpose, audience and tone; output owns the static mailbody, assets and render evidence. Keep recipient instructions in the body, not only in a local file link.
- A process the recipient must follow: make the actual steps and choices visible. Use a step interface only if requested or demonstrably useful; do not conceal necessary instructions behind decorative controls.
- Static structured snapshot: use portable-snapshots when deterministic regeneration is required. A one-off visual may be directly authored; do not build an engine without a need.
- Interactive tool or application: preserve the app's intended behavior and repository ownership. An interactive prototype is not a standalone mailbody.
- Publication: produce the reviewable artifact first and use only the explicitly authorized publishing provider and audience.

Use the format-specific specialist for exact rendering and export. Do not invent commands, adapters or currently unavailable tools.

## Content and audience

Write in the actual sender-to-recipient voice. Keep internal analysis, test logs, implementation notes and local paths outside recipient content. Preserve necessary source, confidentiality, draft status and uncertainty notices: shareable does not mean public or final.

Before including a source fact, image, quote or screenshot, check both its content and audience permission. Access to a source does not prove permission to redistribute it. Do not invent metrics, logos, testimonials, citations or recipient-accessible URLs.

Convert appropriate text into a useful visual rather than decorate it. Put activities and time in the same component, or represent actual dependencies as a sequence. Necessary explanation stays by its component once. If a reusable standalone block is requested, make it understandable without the surrounding email and deliver a separate static representation as requested.

## Produce and validate final bytes

Run any configured plan/format choice before creation. Work in the explicit output location with exact preimages when changing an existing file. Preserve source versions and user edits. For a final artifact:

1. Check the actual file opens or parses with the intended reader. A generated source file is not proof an export works.
2. Render every relevant page, slide, sheet or state; inspect the actual resulting text/images, layout, labels and links. For responsive HTML inspect desktop and a narrow mobile viewport; static content must remain available without page scripts where portability is promised.
3. Verify requested completeness and key domain invariants: formulas, totals, expected sections, exact destinations, images, page/slide counts or interaction states as applicable.
4. Remove accidental placeholders, scaffold instructions, empty sections, fake links and omitted-content markers from final output. An intentional draft/prototype may retain named gaps, but it must be labelled and not called finished.
5. Apply the relevant copy/accessibility checks. Extra interface prose must prevent a concrete mistake or add actual content; a template text slot is not permission for filler. Inspect again after deleting text.
6. Run the configured format checker against the final bytes and repeat affected validation after a repair.

For mail, use one column, inline styles and static tables/images where necessary. Do not depend on scripts, external fonts, app controls, Mermaid or SVG behavior in a recipient mail client. Keep a full text fallback and separate PNG/JPEG assets. Browser rendering does not prove paste behavior or a received email. State untested recipient-app behavior accurately; do not manufacture a trial or send a message to test it without authorization.

If the user requested editable native output, retain it even when also giving a convenient preview. If printable output matters, inspect the actual print/PDF pagination. Keep canonical data distinct from derived projections and follow the selected owner's retention policy rather than mandating a particular database or cloud.

## Finish

Return the usable artifact link/path, what changed and the relevant verification, with material limits. Report publication only when it actually occurred. Source generation, an open browser tab or a polished screenshot does not prove final export, deployment, recipient access or sending.
