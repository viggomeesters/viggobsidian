# Visual and copy verification

Read the actual screen text, not just source strings. Interfaces begin with content, labels and actions. Each extra explanation must prevent a concrete wrong action or interpretation; otherwise remove it. Do not add automatic subtitles, slogans, welcome prose, decorative eyebrow labels or closing commentary. Preserve necessary accessibility names, errors, permission and consequences.

Scan known filler phrases as a supporting check, then assess meaning. A clean scan does not prove useful copy. Inspect the final rendered screen after the last change, including relevant narrow layout, long labels, empty/loading/error states, keyboard interaction and contrast. Use realistic content. Check that hierarchy exposes the next real action and that labels match resulting behavior. Do not explain this checking process inside the product.

Background/headless routes are preferred when reliable. Taking over user focus, mouse or keyboard requires the applicable permission. A screenshot is evidence only for the visible state; verify interaction and persistence separately when relevant.
