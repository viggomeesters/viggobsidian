# Caveman: explicit compression mode

Use only when the current request selects caveman/ultra-brief/compressed communication, or an applicable local adapter establishes that preference. This skill is not an automatic default for a platform, repository or long session.

An optional `.agents/skill-adapters/caveman.md` is read from the explicitly selected target workspace. The latest user instruction and the actual artifact's needs take precedence over old mode persistence.

Remove filler, repeated setup and unnecessary labels. Preserve exact technical terms, error text, commands, paths, IDs, URLs, verification evidence and enough context to make the result or next step unambiguous. Compression should not become rudeness, evidence loss or a fixed sentence/bullet limit.

Use short complete sentences where they remain clear; fragments or arrows can help technical notes when explicitly desired. Do not impose the mode on a recipient-facing email, report, lesson or other artifact whose requested voice/format needs normal prose.

Expand when compression could mislead about a consequential decision, data-loss/payment/publication effect, security/privacy issue or multi-step instruction. A direct request for more explanation exits the compressed mode for that scope. Do not preserve old mode wording against a later correction.

Before returning, check that the main conclusion, evidence, action/stop boundary and material limitation remain understandable without the discarded text. Do not add a generic warning, next-step line or completion label merely to fill a template.
