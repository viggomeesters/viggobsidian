# Durable session evidence and memory

Raw interactions, assistant text and tool output are evidence, not automatically accepted facts about a person. Keep original source identity, chronology and provenance separate from extracted candidates and explicitly accepted durable context. Operational tasks have their own owner and must not become generic memories.

With an explicitly selected target root, read `.agents/skill-adapters/life-os-memory-pipeline.md` for the active archive provider, authorized source scope, supported export/verification/restore route and durable memory owner. Never derive those roots from this installed skill's source location. Without a required provider or permission, stop that archive/write effect; do not inspect a different personal runtime or reactivate a retired producer as fallback.

1. Pin the exact requested producer/session and available source revision. Preserve message IDs, timestamps, attachments and source hashes rather than reconstructing them from names.
2. Export the authorized source through its supported provider. Verify the actual archive, manifests and retrievable records. Do not report a proposed backup as durable evidence.
3. Test restoration only into an explicit new isolated evidence destination. Preserve the operational database; a portable evidence archive is not automatically a drop-in working runtime backup.
4. Keep extracted memory candidates linked to original passages. Distinguish uncertainty, inference, conflicting episodes and user acceptance. Never join a new life episode to an old one merely because topic words match.
5. Use the actual supported durable writer for accepted context. Runtime fact stores, retrieval/vector indexes and generated context are rebuildable projections unless their contract explicitly establishes a different authority.

Whole-vault context compilation, operational restore, synchronization and scheduling are separate outcomes. Preserve local backup/data-unit boundaries and existing writer authority. Do not claim them from a successful chat export alone.

Report what source was preserved, where, what readback/restore was proven, what remains only a candidate and any missing access or provider. Do not publish personal evidence, update memory or create tasks merely because the archive was read.
